# Seneca Remote Harness — Specification

**For:** Cicero · **Repo:** `turneralexander55/Invictus` · **Date:** 2026-10-05
**Purpose:** Give Seneca scoped, killable shell access to Joseph's Arch Linux
workstation (RX 6700 XT) for ML training work — ROCm setup, VLM fine-tuning,
automated test runs. Built by Cicero, controlled by Joseph.

---

## 1. Design principles

- **Least privilege.** Seneca can only touch the project directory tree.
  Nothing else on the machine is reachable.
- **Kill switch.** One command on Joseph's end stops the harness entirely.
  No cleanup needed, no lingering access.
- **Auditability.** Every command Seneca runs is logged with timestamp.
  Joseph can read the log any time.
- **No inbound ports.** The harness polls out (or uses Tailscale); Joseph's
  machine never exposes a listening port to the internet.

## 2. Architecture

```
Joseph's Arch machine                    Seneca (Muse)
┌─────────────────────┐                  ┌──────────────┐
│ harness daemon       │◄──poll/HTTPS────►│ tool calls   │
│  - scoped shell     │                  └──────────────┘
│  - file transfer    │
│  - process manager  │
│  - audit log        │
└─────────────────────┘
```

Cicero's choice on transport: HTTPS polling to a lightweight broker, or
Tailscale + local API. Either is fine as long as §1 holds. Recommended:
a small Python (FastAPI) or Go daemon, systemd user service.

## 3. API surface (what Seneca needs)

### 3.1 Execute command
```
POST /exec
{ "cmd": "string", "cwd": "string (under project root)", "timeout_s": int }
→ { "exit_code": int, "stdout": "string", "stderr": "string", "timed_out": bool }
```
- `cwd` must resolve under the project root; reject anything else.
- Blocklist: no `sudo`, no `su`, no writes outside project root, no
  network listeners, no package manager installs outside a pre-approved
  list (pacman/paru for ROCm stack — Joseph pre-approves the package set).
- `timeout_s` max 300 for foreground; see §3.3 for long-running.

### 3.2 File transfer
```
POST /files/upload   (multipart, dest under project root)
GET  /files/download?path=<under project root>
GET  /files/list?dir=<under project root>
```
- All paths jailed to project root. Resolve symlinks, reject escapes.

### 3.3 Process manager (for training runs)
```
POST /proc/start   { "cmd": "...", "cwd": "..." } → { "proc_id": "..." }
GET  /proc/status?proc_id=... → { "running": bool, "exit_code": int|null }
GET  /proc/logs?proc_id=...&offset=N → { "output": "string" }
POST /proc/kill    { "proc_id": "..." }
```
- Training runs for hours; the poll model must not drop them.
- Cap concurrent processes (suggest max 4). Cap per-process RAM if easy.

### 3.4 Health
```
GET /health → { "ok": true, "gpu": "RX 6700 XT", "rocm": "version|string|null" }
```

## 4. Authentication

- Pre-shared bearer token, generated by Joseph, stored in his Secure Vault.
  Seneca receives it at harness-start; Joseph can rotate any time
  (rotation = old token dies instantly).
- Token scopes to this harness only. It is not a system credential.

## 5. Kill switch

- `systemctl --user stop seneca-harness` — Joseph runs this, everything ends.
- Optional: a desktop shortcut / single command alias (`seneca-kill`).
- When stopped: no listening, no polling, no residual access. Token
  remains valid for next start but does nothing while daemon is down.
- Joseph can also `rm -rf` the project directory; the harness must not
  recreate or repair itself.

## 6. Audit log

- Append-only log at `~/.local/share/seneca-harness/audit.log`:
  `timestamp | endpoint | cmd (truncated 500 chars) | exit_code`
- File uploads/downloads logged with path + byte count.
- Joseph owns this file; the harness never deletes or rotates it
  (logrotate config is fine, deletion by the daemon is not).

## 7. Project root layout (on Joseph's machine)

```
~/seneca-work/
├── scripts/        # training scripts, test runners (Seneca writes here)
├── data/           # training data, photos (Seneca writes here)
├── models/         # downloaded base models, LoRA adapters, GGUF exports
├── runs/           # training outputs, logs, checkpoints
└── README.md       # Joseph's notes
```

Seneca cannot see or touch anything outside `~/seneca-work/`.

## 8. Out of scope (v1)

- No access to Joseph's phone, GitHub tokens, or other credentials.
- No autonomous package installation beyond the pre-approved ROCm set.
- No outbound network from training processes except HuggingFace
  (model downloads) — configurable allowlist.

## 9. Acceptance

Cicero demos: start daemon → Seneca runs `rocm-smi` via /exec →
uploads a script → starts a 60-second sleep via /proc/start → reads logs →
Joseph hits the kill switch → Seneca's next call fails. Done.
