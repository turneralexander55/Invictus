# Reuse catalog

Shared pieces in this repo. Search here, then the code, before building
anything new (charter rule "Reuse before building"). The lead engineer who
merges a new shared piece adds it here in the same merge.

Each entry: what it is, where it lives, how to reuse it, and its tests.

## Packaging and CI

| Piece | Where | Reuse it for | Tests |
|---|---|---|---|
| Repo build script | `scripts/build-repo.sh` | Building any `pkgs/*/*/PKGBUILD` into `[invictus-testing]`, locally (Arch or a container) or in CI. Reuses published versions, signs in a separate step (with `--in-container`: builds in the container with no key, signs on the host, one command), keeps signing variables out of package code, fetches the pinned set, stores GitHub-safe names, refuses packages of 2 GiB or more. `--only NAME` builds one PKGBUILD | `tests/pkgs/e2e-arch.sh`, `e2e-adopt.sh`, `e2e-container-sign.sh` |
| Pinned binary packages | `pkgs/pinned/*.lock` (`hypr.lock` from Arch, `cachyos.lock` from CachyOS), `scripts/fetch-pinned.sh` | Serving any signed binary package at a fixed version from our repo. From Arch: add it to a lock with `--lock name=version-pkgrel` (Arch's signature and the sha256). From another repo: a lock with `#@ source`, `#@ key FILE FINGERPRINT` (only that key may sign) and optionally `#@ fallback` (our published copy, by sha256); never add that repo to an installed pacman.conf. The source goes in `sources.txt` as `pinned` | `tests/pkgs/run.sh` group 9 |
| Repo file names | `scripts/lib/repo-names.sh` (`repo_file_name`) | Any file that goes into the repo or a release asset | `tests/pkgs/run.sh` group 9, `e2e-adopt.sh` (epoch) |
| Adopting an existing install | `scripts/dev/adopt.sh` | Moving any machine set up by the old scripts onto the packages; dry run, backups, undo | `tests/pkgs/e2e-adopt.sh` |
| Meta package pattern and the sets | `pkgs/meta/*/PKGBUILD`, `docs/packages.md`, `pkgs/meta/sources.txt` | New software goes into the one set whose job it is (docs/packages.md says which); a new set is a depends-only meta. One package, one set; `invictus-desktop` never relies on `invictus-base`. Every command the Hyprland config runs maps to a package (`COMMAND_PACKAGES` in `tests/hyprland-lua/run.lua`), every other command our config or scripts run is in `tests/pkgs/fixtures/commands.txt`. After adding a name, run `tests/pkgs/live-arch.sh --write` in Arch to record its source | `tests/hyprland-lua`, `tests/pkgs/run.sh` group 2b, `tests/pkgs/live-arch.sh` |
| Keyring package | `pkgs/own/invictus-keyring` | The one place the repo's public key lives; `invictus-trusted` is derived from it at build time | `tests/pkgs/run.sh`, `tests/pkgs/e2e-arch.sh` |
| Lua config test harness | `tests/hyprland-lua/` (`mock_hl.lua` checks every `hl.*` call against the 0.56.2 stubs and xkbcommon keysyms; `hyprlang.lua` parses old `.conf` files; `hyprrequire.lua` emulates Hyprland's `require`) | Testing any Hyprland Lua without Hyprland, including `invictus-doctor --hypr` (design 1.5), which should load the config through this mock rather than a new one | itself |
| Signed-repo end-to-end test | `tests/pkgs/e2e-arch.sh` | Any change to signing, repo layout or the keyring: builds, signs with a throwaway key, installs with `SigLevel = Required` in a container | itself |
| Live package check | `tests/pkgs/live-arch.sh` | Asking "does this package exist, where, and does everything still install together?" in an Arch container: reads Arch's databases into a throwaway `--dbpath`, the AUR over RPC, and checks conflicts that `pacman -Sp` does not | itself (5 mutations) |
| AUR pin | `pkgs/aur/<name>/PKGBUILD` (header: `aur-commit:`, `Reviewed ... by`, our changes, `Update:`), signers' keys in `keys/pgp/`, optional `upstream-check.sh` | Any AUR package a set needs: copy the AUR commit, review, pin every checksum (signatures too), keep the signer's key; `build-repo.sh` builds it into our repo. Big ones go in `tests/pkgs/fixtures/aur-heavy.txt` | `tests/pkgs/run.sh` groups 2b, 11; CI `aur-pins` |
| AUR bump | `scripts/dev/bump-aur.sh` (`--check`, `NAME --reviewer WHO`) | Moving any pin to a newer AUR commit: shows the AUR diff, applies version-and-checksum-only changes, recomputes and cross-checks checksums with the AUR's, checks signatures. Never write a new updater | `tests/pkgs/run.sh` group 11 |
| Package version vs contents | `scripts/dev/pkg-inputs.py` (`--check`, `--update`, `--update --rehash NAME`, `--inputs NAME`), `pkgs/inputs.lock` | Knowing which own or meta package a change touches and making sure it gets a new pkgrel: after changing anything a PKGBUILD installs, bump that package and run `--update`. `--inputs NAME` lists the files a package is built from. No git needed | `tests/pkgs/run.sh` group 1b |
| The AI set | `scripts/lib/ai-set.sh` (`AI_METAS`, `AI_PKGS`, `AI_ON_INSTALL`; installed as `/usr/lib/invictus/lib/ai-set.sh`), `tests/pkgs/no-ai-in-base.sh` | Any check or verb that needs to know what a No AI machine must not have (design-no-ai.md N5): `invictus-sys ai on|off` installs and removes from it. Add new AI packages to the list, not to each test | `tests/pkgs/run.sh` group 2b, `e2e-arch.sh`, CI `no-ai-in-base` |
| Heavy-pin stand-ins | `tests/pkgs/lib/aur-heavy.sh` (`stand_in_heavy_aur`) | An e2e test that builds the repo but does not need the real big AUR packages | `e2e-arch.sh`, `e2e-adopt.sh` |
| Pinned CI tools | `.github/workflows/checks.yml` | Actions pinned by commit, binaries by checksum. Copy the gitleaks install step for any new downloaded tool | CI |
